# Distributed Systems Failure Simulator (DSFS)

DSFS — симулятор распределённых систем на Rust. Проект позволяет запускать кластеры узлов, моделировать сетевые проблемы, отключения узлов и проверять, как система ведёт себя в разных ситуациях.

Основная идея — сделать симуляцию полностью воспроизводимой. Если при определённом сценарии возникает ошибка, её можно повторить с тем же seed и посмотреть, что именно произошло.

## Возможности

- Симуляция распределённой системы с виртуальным временем.
- Собственная реализация алгоритма Raft.
- Выборы лидера, heartbeat-сообщения и репликация лога.
- Моделирование сетевых задержек, потерь и дублирования сообщений.
- Создание сетевых разделений (network partitions).
- Отключение и перезапуск узлов.
- Запуск сценариев из YAML-файлов.
- Запись событий в JSONL-журнал.
- Проверка корректности работы системы с помощью отдельного checker.
- Повторный запуск сценариев для проверки воспроизводимости.
- Property-тесты и бенчмарки.

Некоторые возможности Raft пока не реализованы: snapshots, изменение состава кластера и pre-vote. Подробнее об ограничениях написано в `docs/raft.md`.

## Установка и запуск

Сборка проекта:

```bash
cargo build --release
```

Инициализация:

```bash
./target/release/dsfs init --force
```

Запуск примера:

```bash
./target/release/dsfs run configs/scenarios/example.yaml
```

Посмотреть журнал:

```bash
./target/release/dsfs inspect results/latest.jsonl
```

Проверить инварианты:

```bash
./target/release/dsfs validate results/latest.jsonl
```

Повторить запуск:

```bash
./target/release/dsfs replay results/latest.jsonl
```

Команда `validate` возвращает:
- `0` — все проверки пройдены;
- `1` — обнаружены нарушения;
- `2` — ошибка ввода-вывода.

## Пример сценария

Сценарии описываются в YAML. Например, можно дождаться выбора лидера, отключить один из узлов, дождаться нового лидера и отправить запись.

```yaml
version: 1
name: leader_failure
seed: 42

cluster:
  nodes: 5
  raft:
    election_timeout_ms: 150
    heartbeat_interval_ms: 30

network:
  default:
    base_latency_ms: 5
    jitter_ms: 2
    loss_probability: 0.0
    duplicate_probability: 0.0

events:
  - wait_for_leader: {}

  - at_ms: 1000
    crash_node: 3

  - wait_for_leader: {}

  - at_ms: 3000
    submit_write:
      key: balance
      value: "500"
```

`wait_for_leader` позволяет дождаться появления лидера перед выполнением следующих событий. Это ожидание состояния системы, а не обычная задержка по времени.

## Структура проекта

Проект разделён на несколько основных частей:

| Компонент | Описание |
|---|---|
| `dsfs-raft` | Реализация Raft и логика работы узлов |
| `dsfs-core` | Основной движок симуляции, сеть и обработка событий |
| `dsfs-checker` | Проверка журналов и инвариантов |
| `dsfs-cli` | Консольный интерфейс для работы с симулятором |

Дополнительная документация находится в папке `docs`:

- `architecture.md` — архитектура проекта.
- `failure-model.md` — модель отказов и её ограничения.
- `design-decisions.md` — основные технические решения.
- `raft.md` — особенности реализации Raft.

## Детерминизм

Одна из основных особенностей проекта — возможность повторить симуляцию с теми же результатами.

Для этого используются:

- Виртуальное время вместо системных часов.
- Фиксированный порядок обработки событий.
- Seed для генератора случайных чисел.
- Отдельные потоки случайных чисел для разных частей симуляции.
- Узлы, работающие как независимые state machine.

При одинаковой конфигурации и seed два запуска должны давать одинаковые журналы событий.

Команда `replay` повторно запускает сценарий и сравнивает полученный результат с исходным журналом. Если результаты отличаются, значит, в реализации есть проблема.

## Тестирование

Запустить все тесты:

```bash
cargo test --workspace
```

Запустить бенчмарки:

```bash
cargo bench -p dsfs-core
```

В проекте есть unit-, integration- и property-тесты.

Property-тесты генерируют случайные сценарии с отключениями узлов, задержками и отправкой записей. В процессе проверяется:

- Совпадение результатов двух запусков с одинаковым seed.
- Отсутствие нарушений проверяемых инвариантов.
- Возможность выбрать хотя бы одного лидера.

## Производительность

Бенчмарки запускались на Intel Core i5 (12 потоков) под Linux Mint 22.3.

Результаты команды `cargo bench -p dsfs-core --bench engine_throughput`:

| Кластер | Количество событий | Время | Скорость |
|---|---:|---:|---:|
| 3 узла | 10 000 | ~1.12 мс | ~8.9 млн событий/сек |
| 5 узлов | 10 000 | ~1.24 мс | ~8.1 млн событий/сек |
| 5 узлов | 100 000 | ~12.5 мс | ~8.0 млн событий/сек |

Замеры проводились в одном процессе с использованием in-memory журнала. При включении JSONL-логирования и изменении конфигурации сети результаты могут отличаться.
